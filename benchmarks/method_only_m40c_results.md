# M40c: method JIT 単独と main の比較

候補は tracing frontend、記録用 dispatch、side trace を削除し、静的 method JIT と Tier 1 fallback だけを使う。時間比は candidate / main。小さいほど速く、各結果 1.10 以下を目標とする。

GIL は tracing JIT と method JIT の比較。固定 main の FT build は JIT を要求しても executor を作らないため、FT は Tier 1 と method JIT の比較になる。FT 候補も複数スレッドの共存時には Tier 1 へ戻る。

候補には C 実装や共通 optimizer の修正も含まれる。ブランチ全体の比較であり、frontend の変更だけによる因果効果とは扱わない。両者とも C `_decimal` を使う。

## 全体結果

| 構成 | 比較できた結果数 | 未完了の仕様数 | 時間比の幾何平均 | 1.10 超 |
|---|---:|---:|---:|---:|
| ft | 122 | 2 | 0.9281 | 0 |
| gil-pgo-lto | 122 | 2 | 0.9792 | 6 |

各 worker の平均を同じ重みで集計し、両順序の比を幾何平均する。95%区間は block 内の worker を再標本化した bootstrap（4,000回）。すべての測定 worker を保持する。未完了の仕様は幾何平均に混ぜない。

## 固定 build と検証

main は `d95f29589e03603aa13d8ca9d4f817dce77d357c` に LLVM 21 build 対応を加えたもの。候補は `m40c-method-only.patch` のスナップショット。開発比較では PGO/LTO を使用せず、最終 GIL build だけ PGO/full-LTO を有効にした。FT は O3、PGO/LTOなし。

| Build | SHA-256 |
|---|---|
| r0-ft-main | `44c9f1615910b76898e1eb6cd478a36c151f21cf5bc99ea95aa6ac115c85fefb` |
| r0-gil-main | `29f98fde43417b99bad02a6710ad55e55f343a574f8fff306932d1e75b010044` |
| m40c-ft-release | `a3d144e5e8df2460041dfeb7be350a6cce42442a4f0afcd3f8f953a6e25e0fdb` |
| m40c-gil-pgo-lto | `70920f0a2bf782feab44bd448cd709ff433ac44ef66835c911ab4beda6d969b8` |

最終 native build では両構成とも test_opt 561件、属性・呼び出し・monitoring・generator 589件、C関連1,154件、JIT無効の属性キャッシュ97件が成功。FT/GIL debugの新規range境界・module binding・算術特殊化変更テストと参照リーク検査も実施した。各groupのskipと実行コマンドは m40c-final-validation.json および対応ログに保存した。既存のtracing固有の期待はmethod CFGの検証へ移行しており、旧最適化がすべて移植されたという意味ではない。

CPU 2 に固定し、3 worker × 5 warmup × 5 value、最小測定時間0.1秒。ループ数は両者が独立に校正する。各仕様は同じblock内で両者を続けて測定し、次blockで順序を反転する。FTとGILは順次実行しており、構成間の直接的な因果比較ではない。測定中にビルドやテストを並行実行していない。
